# Налаштування акаунтів Feler

Навчальні маршрути працюють і без реєстрації. Supabase потрібен для входу та синхронізації прогресу й чернеток між пристроями.

## Налаштування

1. Створи проєкт у [Supabase](https://supabase.com/).
2. У **Project Settings → API** скопіюй Project URL та публічний `anon`/publishable key.
3. Встав їх у `supabase-config.js`:

   ```js
   window.FELER_SUPABASE_CONFIG = {
     url: "https://YOUR_PROJECT.supabase.co",
     anonKey: "YOUR_PUBLIC_ANON_KEY"
   };
   ```

4. Відкрий **SQL Editor** у Supabase, встав вміст `supabase-schema.sql` і виконай його. Скрипт створює таблицю прогресу та вмикає Row Level Security, щоб користувач мав доступ лише до власного рядка.
5. У **Authentication → URL Configuration** встанови:
   - **Site URL:** `https://liwb1om.github.io/feler/feler/`
   - **Redirect URLs:** додай `https://liwb1om.github.io/feler/feler/**`
   - Для локальної розробки окремо додай адресу локального сервера, наприклад `http://localhost:8765/**`.

   Реєстраційний лист повертає користувача на сторінку, з якої він зареєструвався. Ця адреса має бути дозволена в Redirect URLs.
6. У **Authentication → Providers → Email** налаштуй підтвердження email. Якщо воно увімкнене, після реєстрації користувачеві потрібно підтвердити пошту, а потім увійти.
7. Розмісти сайт на HTTPS і протестуй реєстрацію, вхід, вихід та синхронізацію.

Якщо повторна реєстрація показує «Запит прийнято», це не гарантує, що створився новий користувач або що лист був відправлений: Supabase навмисно не розкриває, чи існує адреса. Перевір **Authentication → Users** і використовуй кнопку повторного надсилання в формі. Для користувача, що вже підтвердив адресу, входь із правильним паролем; повторне надсилання листа не скидає пароль.

## Безпека й поведінка

- У клієнтський `supabase-config.js` можна додавати лише Project URL та публічний anon/publishable key. **Не додавай `service_role` key**: він обходить RLS.
- Пароль обробляє Supabase Auth; сайт не записує його у власне сховище.
- Гостьовий прогрес залишається локальним на пристрої. Він не переноситься автоматично в новий акаунт.
- Дані кожного акаунта зберігаються окремо. Гостьовий режим залишається доступним після виходу.
